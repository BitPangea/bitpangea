Reference Vector Section 06 · Canonical Convergence

The canonical test set for proving that equivalent syntactic or mathematical representations converge deterministically to one authoritative Survey meaning, with one unique representation only where the Specification requires it.

Normalization Vectors define exact executable cases proving that valid equivalent CRPC, Segment, SCPE, and FSF-CJSON representations converge deterministically without changing canonical spatial meaning.

The integrated candidate Specification now resolves the principal normalization rules that were previously open: CRPC reduction, canonical zero, lexicographic Point order, deterministic Segment endpoint order, SCPE normalization, normalization idempotence, and FSF-CJSON-1.0 canonical serialization.

Reference Vectors may therefore move from abstract normalization categories into exact candidate fixtures. The remaining boundaries concern forms not yet defined by the Specification—such as future human-facing aliases, unresolved higher geometry, and any interchange form outside the current canonical FSF-CJSON profile.

Reference Vector Question Given this exact input, what exact answer must every conforming implementation produce?
06.0 · Current Normalization Model

Normalization Is Now a Deterministic Candidate Function

The candidate mathematics define normalization over supported canonical objects rather than treating normalization as an open future concept.

At minimum, the executable normalization surface includes CRPC values, Points through normalized components, Segments, SCPEs, and FSF-CJSON-1.0 canonical serialization.

Normalization may change representation. It may not change exact spatial meaning.

06.1 · CRPC Reduction Vectors

Equivalent Rational Values Must Reduce Identically

Reference Vectors shall include valid mathematically equivalent rational inputs whose canonical result is one reduced CRPC value.

The normalization rules include greatest-common-divisor reduction, positive denominator, normalized sign, and canonical zero as 0/1.

06.2 · Canonical Point Vectors

Point Normalization Is Component Normalization

A Point is canonical when its x and y CRPC components are canonical.

Differently expressed valid rational components that denote the same exact values shall normalize to the same canonical Point.

06.3 · Segment Normalization Vectors

Segment Endpoint Order Must Be Deterministic

Reference Vectors shall include the same valid Segment supplied with reversed endpoint order.

Canonical Segment normalization orders the two endpoints lexicographically so that equivalent endpoint permutations produce one canonical Segment representation.

06.4 · SCPE Traversal Normalization Vectors

Equivalent Polygon Traversals Must Converge

Reference Vectors shall include valid SCPE representations differing only by traversal direction or starting vertex.

Canonical normalization selects counterclockwise traversal and then selects the unique lexicographically least vertex as the canonical start vertex.

06.5 · Redundant Collinear Vertex Vectors

Redundant Middle Vertices Must Disappear Deterministically

Where a valid SCPE contains a vertex lying exactly between adjacent collinear vertices, normalization removes that redundant middle vertex.

The reduction shall repeat to a fixed point so that equivalent polygonal boundaries do not acquire distinct canonical forms merely because one input contains unnecessary collinear subdivision.

06.6 · Closure-Point Vectors

Repeated Terminal Closure Must Not Create Alternate Geometry

Where an accepted input form repeats the first SCPE vertex as a terminal closure marker, Reference Vectors shall prove that canonical normalization removes the repeated terminal Point.

The canonical SCPE representation stores the cycle without duplicating the first vertex at the end.

06.7 · Canonical Geometry Equality Vectors

Equivalent Supported Geometry Must Normalize to Equality

Reference Vectors shall demonstrate that valid supported geometry representing the same canonical spatial set produces identical normalized geometry.

Semantic equivalence shall therefore be reproducible through exact normalization rather than visual similarity or implementation-specific simplification.

06.8 · FSF-CJSON Canonical Serialization Vectors

Canonical Objects Must Produce Canonical Bytes

Reference Vectors shall include canonical FSF-CJSON-1.0 objects and exact expected serialization where the profile requires one canonical byte sequence.

The corpus shall prove canonical integer-string representation, required object structure, deterministic key ordering, prohibited unknown fields where applicable, UTF-8 encoding, and exact canonical bytes.

06.9 · Parse / Normalize / Serialize Vectors

Canonical Round-Trip Must Converge

Where a valid supported noncanonical input form is permitted, vectors shall demonstrate the deterministic path:

parse → validate → normalize → canonical object → canonical serialize.

Repeating the process on the canonical output shall produce the same canonical object and the same canonical bytes.

06.10 · Idempotence Vectors

Normalizing Canonical Output Again Must Change Nothing

For every supported normalized object G, Reference Vectors shall prove:

N(N(G)) = N(G).

Idempotence applies to the mathematical canonical object and, where canonical serialization is defined, to the resulting canonical representation.

06.11 · No-Snapping Vectors

Normalization Must Never Move Place

Reference Vectors shall include exact Points and geometry near other representable values to prove that normalization performs only permitted exact canonicalization.

It shall not round, snap, approximate, quantize, migrate, or otherwise change the represented position or extent.

06.12 · Exactness-Preservation Vectors

Normalization Cannot Become Lossy Conversion

Exact CRPC values and geometry shall retain all canonical mathematical information through normalization.

Any operation that truncates, rounds, decimalizes, generalizes, or otherwise loses information belongs to a lossy conversion pathway and shall not be reported as canonical normalization.

06.13 · Invalid Normalization Boundary Vectors

Invalid Input Must Remain Invalid

Reference Vectors shall include malformed CRPC, malformed geometry, invalid SCPEs, prohibited serialization forms, duplicate or unknown fields where forbidden, and other invalid cases that superficially resemble normalizable input.

A conforming implementation shall reject those cases rather than infer intent or silently repair them into canonical validity.

06.14 · Representation-Boundary Vectors

Only Defined Alternate Forms May Participate in Normalization

The current candidate profile supports normalization and canonical serialization for the representations explicitly defined by the Specification.

Future aliases, human-readable syntaxes, alternate interchange formats, or geometry families shall not be treated as valid normalization inputs until the Specification formally defines their semantics and conversion rules.

06.15 · Cross-Implementation Normalization Agreement

Every Implementation Must Converge to the Same Canonical Result

Independent conforming implementations shall produce the same normalized CRPC, Point, Segment, SCPE, and canonical FSF-CJSON result for identical supported inputs.

A mismatch indicates implementation defect, Specification ambiguity, version incompatibility, fixture defect, or an input form tested beyond the current normalization contract.

Executable Now

CRPC reduction; canonical zero; Point component normalization; Segment endpoint ordering; SCPE traversal normalization; redundant-collinear removal; closure-point removal; lexicographically least SCPE start; normalization idempotence; exactness preservation; no snapping; FSF-CJSON canonical serialization; parse/normalize/serialize round-trip.

Still Open or Conditional

Future human-facing aliases; alternate address syntaxes not yet specified; interchange formats outside FSF-CJSON-1.0; normalization of future geometry families or general composite geometry; final vector identifiers and corpus packaging.

Reference Vector Integration Standing

Normalization Is Now One of the Strongest Executable FSF Proof Surfaces

The original page correctly deferred the corpus while addressing, geometry, ordering, serialization, and normalization algorithms were unresolved. Those dependencies are now substantially defined for the candidate core.

Section 06 can therefore support exact executable Reference Vectors across CRPC, Segment, SCPE, and FSF-CJSON normalization. The remaining work is concentrated in future representations and geometry families that the Specification has not yet admitted.
