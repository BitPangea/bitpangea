Foundational Survey Fabric · Canonical Test Corpus Framework

The canonical examples and test cases through which expected Foundational Survey Fabric results become independently reproducible.

Foundational Survey Fabric Reference Vectors define the exact input-and-expected-result cases through which independent implementations prove agreement with the governing Specification and Conformance framework.

Reference Vectors do not select Survey mathematics. The Requirements establish what must be satisfied. The Specification defines the mathematics that satisfies those requirements. Conformance defines how an implementation proves compatibility. Reference Vectors provide canonical examples, negative cases, adversarial cases, and machine-verifiable expected results derived from that already-defined mathematics.

All twelve Reference Vector sections have now been reconciled against the integrated candidate Specification and Conformance architecture. The corpus is no longer uniformly blocked on future mathematics: substantial portions are executable now, while a smaller set of dependencies remains explicitly open.

Current Corpus Standing

Integrated Candidate Reference Vector Architecture

The twelve-section framework now distinguishes three classes of work: executable now, parameterized or conditional, and still open because the Specification has not yet closed the mathematics. Reference Vectors shall advance only within those boundaries.

Executable candidate core: CRPC exact coordinates and arithmetic; canonical Point / Segment / SCPE geometry; exact predicates; deterministic normalization; ECEM meaning preservation; exact SCPE area; canonical orientation frame; restricted exact transformation through translation and positive uniform scale; FSF-CJSON-1.0 canonical interchange; invalid / unsupported separation; Conformance evidence and compatibility testing; and adversarial stress across those defined behaviors.

Parameterized or conditional: Survey Domain boundary behavior using DH = {(x,y) : -H ≤ x ≤ H and -H ≤ y ≤ H}; Domain-edge fixtures may be expressed symbolically or parametrically until the numerical half-span H is selected.

Still open: numerical Survey Domain capacity H; final angular unit; arbitrary exact rotation and its result coordinate class; exact non-rational derived-scalar representation for some distances and lengths; general Boolean / composite result geometry; final complexity ceilings; and final corpus identifiers, packaging, and canonical adoption.

Together, these twelve sections define the integrated candidate Reference Vector architecture for the Foundational Survey Fabric. The corpus now covers exact reference, Domain classification, Pang-based mathematics, orientation, geometry, normalization, transformation, precision, invalid-input handling, canonical interchange, version / Conformance behavior, and adversarial stress.

The corpus remains subordinate to Requirements, Specification, and Conformance. It may prove, expose, compare, reproduce, and stress behavior that the Specification actually defines. It may not invent spatial truth, choose unresolved mathematics, fill missing result types, redefine canonical authority, or allow higher Architecture domains to leak into FSF outcomes.

The correct standing is therefore not “the corpus is blocked until all mathematics are complete.” The correct standing is: build executable vectors for the solved core; use symbolic or parameterized vectors where the governing mathematics is parameterized; and leave unresolved mathematics visibly open until the Specification closes it.

Architectural Sequence Requirements establishes what must be satisfied. Specification defines the mathematics that satisfies it. Conformance defines how an implementation proves it follows the Specification. Reference Vectors provide canonical examples and test cases proving the expected results.
Reference Vector Standing Requirements ownership and reverse traceability remain closed across all twelve sections. The integrated candidate corpus now advances wherever the Specification supplies exact mathematics, remains parameterized where the mathematics is parameterized, and stays explicitly open where the Specification has not yet selected one canonical answer.
