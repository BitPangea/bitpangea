Reference Vector Section 11 · Compatibility and Conformance Outcomes

The canonical test set for proving continuity of spatial truth across compatible specification versions and deterministic conformance outcomes under defined profiles.

Version / Conformance Vectors define the reference cases through which implementations will prove that earlier canonical spatial meaning remains unchanged across compatible specification evolution and that known implementation behavior is classified consistently under a defined conformance profile.

These vectors intentionally join version continuity and conformance disposition because both concern interpretation of the same governing standard over time: what remains canonically unchanged, what a specific implementation is required to support, and whether observed behavior should pass, fail, be unsupported, or remain indeterminate.

Reference Vector Question Given this exact input, what exact answer must every conforming implementation produce?
11.1 · Cross-Version Canonical Meaning Vectors

Compatible Versions Must Preserve Place

The vector set shall include canonical references and expressions established under an earlier compatible specification version together with the authoritative result required under a later compatible version.

The expected result shall demonstrate that established canonical spatial meaning remains unchanged.

11.2 · Cross-Version Result Equivalence Vectors

Unchanged Rules Must Produce Unchanged Results

Reference vectors shall include operations whose semantics are unchanged across compatible specification versions.

Identical canonical inputs shall continue to produce identical authoritative results under each compatible version.

11.3 · Versioned Serialization Vectors

Representation May Evolve Without Moving Canonical Meaning

The corpus shall include versioned serialized forms that represent the same canonical Survey truth under different compatible specifications or interchange formats.

Conforming implementations shall preserve identical underlying spatial meaning even where the representation changes.

11.4 · Backward-Compatibility Vectors

Later Implementations Must Preserve Earlier Canonical Truth

Reference vectors shall include previously valid canonical inputs that a later compatible implementation must continue to interpret correctly.

Compatible evolution shall not make established Survey references ambiguous, invalid, or spatially different.

11.5 · Forward-Compatibility Vectors

Unsupported Future Capability Must Be Identified, Not Guessed

The vector set shall include cases where an implementation encounters a future optional feature, extension, or representation beyond its supported conformance scope.

The expected result shall distinguish unsupported capability from invalid canonical truth and shall prohibit fabricated interpretation.

11.6 · Compatible-Change Vectors

Clarification and Extension Must Preserve Established Truth

The corpus shall include specification changes classified as compatible, such as clarification, additional conformance material, or optional capability.

Reference outcomes shall prove that those changes do not alter established canonical spatial meaning.

11.7 · Incompatible-Change Vectors

Spatial Mutation Must Not Be Classified as Routine Compatibility

Reference vectors shall include hypothetical or historical cases sufficient to demonstrate when a change would renumber, relocate, reinterpret, or otherwise alter established canonical spatial truth.

Such a case shall be classified as incompatible rather than ordinary version evolution.

11.8 · Pass Vectors

Correct Mandatory Behavior Must Pass

The vector set shall include known implementation behaviors that fully satisfy the applicable conformance profile and therefore must receive a passing disposition.

Every evaluator applying the same governing rules shall reach the same result.

11.9 · Fail Vectors

Incorrect Canonical Behavior Must Fail

Reference vectors shall include known implementation results that violate required canonical behavior within the claimed conformance scope.

Such cases shall receive a deterministic failure disposition rather than being excused as implementation variation.

11.10 · Unsupported Vectors

Optional Capability Outside the Claim Must Be Identified Correctly

The corpus shall include cases where an implementation does not support an optional capability outside its declared conformance scope.

Those cases shall be classified as unsupported rather than automatically failing the Mandatory Core.

11.11 · Indeterminate Vectors

Specification Ambiguity Must Not Be Misclassified as Implementation Failure

Where the governing specification does not yet determine one authoritative result, a reference case may be classified as indeterminate until the ambiguity is resolved.

Such cases shall remain visibly distinct from pass, fail, and unsupported outcomes.

11.12 · Conformance Profile Vectors

One Implementation May Have Different Outcomes Under Different Declared Scopes

Reference vectors shall demonstrate how the same observed implementation behavior is evaluated under explicitly different conformance classes or profiles where those distinctions are permitted.

Profile differences shall classify capability, not create alternate canonical spatial truth.

11.13 · Declaration Consistency Vectors

Formal Claims Must Match Proven Outcomes

The vector corpus shall include conformance-report and declaration cases to prove that a formal compatibility claim does not exceed the specification version, conformance profile, or test outcomes actually demonstrated.

A declaration inconsistent with its evidence shall be classified as invalid.

11.14 · Cross-Implementation Conformance Agreement

Independent Evaluators Must Reach the Same Disposition

Independent evaluators applying the same Specification, Conformance rules, profile, and vector input shall reach the same pass, fail, unsupported, indeterminate, or compatibility judgment.

Disagreement indicates ambiguity in the rules, incorrect evaluation, or an unresolved version dependency requiring correction.

Established by Requirements and Conformance Scope

The Survey Fabric must preserve established canonical meaning across compatible specification evolution, identify governing specification versions, distinguish compatible from spatially mutating change, support independently reproducible conformance judgments, and preserve a mandatory core while allowing explicitly scoped optional capability above it.

Canonical Vector Corpus Not Yet Possessed

Actual specification-version pairs, compatibility fixtures, profile identifiers, pass/fail/unsupported/indeterminate examples, transition vectors, declaration cases, and authoritative machine-readable outcomes cannot be created until the versioning model, final conformance profiles, test taxonomy, and declaration format are formally established.
