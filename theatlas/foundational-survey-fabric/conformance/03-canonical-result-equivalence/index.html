Conformance Section 03 · Independent Result Reproducibility

The conformance requirement that independent implementations return identical authoritative results for identical canonical inputs.

Canonical Result Equivalence establishes the central reproducibility test of Foundational Survey Fabric conformance. If two independent implementations receive the same canonical input under the same governing Specification, the authoritative result must be the same.

Internal architecture may differ radically. Programming language, storage model, optimization strategy, caching, indexing, execution order, and implementation technology may all vary. None of those differences may alter canonical spatial truth.

Conformance Principle Many implementations. One spatial truth.
03.1 · Equivalence Requirement

Identical Canonical Inputs, Identical Authoritative Results

Any two conforming implementations shall produce the same authoritative canonical result when given identical valid canonical inputs under the same applicable Specification.

A disagreement in authoritative result indicates a conformance failure, a specification ambiguity, an implementation defect, or an unresolved incompatibility that must be identified rather than silently tolerated.

03.2 · Scope of Equivalence

Equivalence Applies Wherever Canonical Truth Is Produced

Canonical Result Equivalence shall apply to every mandatory operation that produces authoritative Survey truth, including interpretation, normalization, validation, measurement, geometric predicates, composition, comparison, serialization, and other canonical outputs defined by the Specification.

Optional features may add capability, but where they claim canonical behavior they remain subject to the same equivalence requirement.

03.3 · Implementation Independence

Internal Method Does Not Define the Answer

A conforming implementation may use any internal algorithm, programming language, storage engine, indexing strategy, cache, or optimization that preserves the authoritative result.

Internal method is implementation freedom. Canonical output is not.

03.4 · Exact Equivalence

Canonical Equality Is Exact

Authoritative result equivalence shall be determined by the exact canonical rules of the Specification rather than tolerance bands, approximate numeric agreement, implementation-specific rounding, or “close enough” comparison.

Where a result is canonical, equivalent means mathematically equivalent under the governing Survey rules.

03.5 · Canonicalization Before Comparison

Compare Meaning in Canonical Form

Where multiple valid noncanonical expressions can represent the same canonical spatial meaning, conforming implementations shall first normalize those expressions according to the governing canonicalization rules.

Result comparison shall distinguish harmless representational variation from actual disagreement in canonical meaning.

03.6 · Serialization Equivalence

Authoritative Interchange Must Agree

When a canonical result is serialized for authoritative interchange, conforming implementations shall produce or normalize to the same canonical serialized representation required by the Specification.

Different internal or presentation formats are permissible only where they map deterministically to the same authoritative interchange truth.

03.7 · Validation Equivalence

The Same Input Must Receive the Same Canonical Judgment

Independent implementations shall reach the same canonical validity judgment for the same input under the same Specification.

An input shall not be canonical in one conforming implementation and invalid, ambiguous, or differently interpreted in another.

03.8 · Error Equivalence

Invalid Inputs Must Fail Consistently

Where the Specification defines an input or operation as invalid, conforming implementations shall reject it consistently according to the applicable failure rules.

Implementations may expose different human-readable diagnostics, but they shall not invent canonical meaning for an input that another conforming implementation correctly rejects.

03.9 · Hidden-State Prohibition

Equivalent Results Must Not Depend on Hidden Context

Cache state, database sequence, randomization, user identity, ownership state, session context, wall-clock time, or other mutable implementation conditions shall not cause canonical results to differ.

Hidden state may improve performance. It may not participate in foundational spatial meaning.

03.10 · Reference Vector Proof

Equivalence Must Be Testable

Canonical Result Equivalence shall ultimately be demonstrated through shared reference vectors containing defined canonical inputs and their required authoritative results.

A conforming implementation shall reproduce the required results exactly for every Mandatory Core vector applicable to its conformance claim.

03.11 · Cross-Implementation Testing

Independent Implementations Should Be Compared Directly

Conformance testing should permit outputs from independent implementations to be compared directly after canonical normalization.

Cross-implementation disagreement is valuable evidence: it should expose ambiguity or defect rather than be concealed by implementation-specific tolerance.

03.12 · Disagreement Handling

Conflict Must Be Resolved at the Correct Layer

If independent implementations produce different authoritative results from the same canonical inputs, the disagreement shall be treated as a conformance or specification issue.

The correct response is to determine whether the Specification is ambiguous, one or more implementations are defective, or incompatible versions are being applied. Consensus or implementation preference shall not simply choose among conflicting mathematical answers.

Established by Requirements

Finding #10 requires independent conforming implementations to derive identical canonical results from identical inputs. Supporting requirements establish exact mathematics, deterministic canonicalization, canonical serialization, exact equivalence, exact comparison, finite representation, hidden-state independence, and deterministic termination.

Still Open in Conformance

The exact comparison harness, reference-vector corpus, canonical output-diff rules, error equivalence taxonomy, cross-version comparison rules, tolerance for noncanonical diagnostics, and formal procedure for resolving implementation disagreement remain to be defined after the Specification is complete.
